# VCM の開始検知（Google Apps Script）

GAS（開始メール検知）は、iPhone アプリからのリクエストを受けて Gmail の Garmin LiveTrack 開始メールを探し、セッション情報を Worker（データの受け渡し）へ登録します。検知後は、アプリで選んだ発話間隔の同期も担当します。走行データの監視とコーチングは `muse/`、音声の受信・再生は iOS アプリが担当します。

初めて導入する場合は、画面操作を含む [SETUP のステップ4](../SETUP.md#step-4) に沿って進めてください。この文書は GAS の設定・更新・動作確認の参照資料です。

## ファイルと前提

| ファイル | 用途 |
|---|---|
| [livetrack_detector.gs](livetrack_detector.gs) | Apps Script に貼り付けるコード |
| [test_processed.cjs](test_processed.cjs) | Gmail・Worker を模擬したローカルテスト |

Muse 環境へのプログラム配置とは別に、Google Apps Script へ配置します。

利用には、開始メールが届く Gmail アカウントと、[Worker](../worker/worker.js) の配置が必要です。発話間隔の同期には、Worker の `session-settings` と Muse 側の watcher・monitor も対応している必要があります。

## 初回設定

1. 開始メールを受け取る Google アカウントで Apps Script プロジェクトを作り、`livetrack_detector.gs` の内容を貼り付けます。
2. 「プロジェクトの設定 → スクリプト プロパティ」に次の3項目を登録します。
3. ランが進行していないときに `debugCheck` を実行し、必要な権限を承認して結果を確認します。結果の意味は後述します。
4. ウェブアプリとして初回デプロイします。実行ユーザーは「自分」、アクセスできるユーザーは「全員」にします。
5. 発行された `/exec` URL をアプリの「検知スクリプト URL」、`KICK_SECRET` を「検知スクリプト キー」に設定します。

| プロパティ | 設定する値 |
|---|---|
| `KICK_SECRET` | アプリからの呼び出しを認証する合言葉。アプリ側に同じ値を登録 |
| `UPLOAD_TOKEN` | 自分の Worker に登録した同名シークレットと同じ値 |
| `WORKER_BASE` | 自分の Worker のベースURL。`https://your-worker.example.workers.dev` の形式で、末尾に `/queue.json` や `/upload` を付けない |

秘密値はコードやチャットに書かず、所定の設定欄へ入力します。`KICK_SECRET` と `UPLOAD_TOKEN` は別の用途のため、別々の値を使います。

**時間主導トリガーは登録しません。** 呼び出し元はアプリです。古い `scheduledCheck` のトリガーが残っていれば停止してください。この関数は現在、開始IDのない実行をエラーにします。

## コードを更新する場合

次の順で更新します。

1. 使用中の Apps Script プロジェクトで、コードを最新の `gas/livetrack_detector.gs` に置き換えて保存します。
2. **デプロイ → デプロイを管理 → 使用中のデプロイ → 編集 → 新しいバージョン → デプロイ** と進めます。
3. 同じ `/exec` URL が維持されていることを確認します。

コードを保存しただけでは、アプリが呼ぶ既存デプロイは更新されません。更新のために「新しいデプロイ」を作り直す必要はありません。別のデプロイを作って URL を変えた場合は、アプリ側の URL も更新します。画面ごとの説明は [SETUP の更新手順](../SETUP.md#step-4) を参照してください。

アプリ・Worker・Muse 側も更新が必要な機能については、[SETUP の接続設定・発話間隔](../SETUP.md#step-5)に従います。現在の GAS は `start_id` と `since` を送らない旧アプリには対応しません。

## 開始検知の流れ

通常の操作順は **アプリでコーチング開始 → 時計でアクティビティ開始**です。

1. アプリが受信中に約30秒ごとに GAS を呼び出します。
2. GAS は認証と開始ID・開始時刻を確認し、Gmail の `livetrack newer_than:2h` の検索結果を全ページ調べます。
3. 未処理メールのうち、開始時刻の120秒前以降かつ受信から30分以内で、LiveTrack URL を抽出できる最新の候補を選びます。URL は HTML 本文から抽出し、`gar.mn` の短縮リンクはリダイレクト先を確認します。
4. Worker の `op=session` へ開始ID・LiveTrack のセッションIDとトークンなどを認証付きで送ります。成功した場合だけ、そのメールを処理済みにします。
5. Muse 側の監視フックが登録情報を読み、開始準備を進めます。

検索にまだ反映されていない新着メールは検知できません。120秒は時計ずれの許容であり、その範囲内の開始前メールも候補になるため、検索反映の遅れによる誤選択を完全には防げません。

**`found:true` は、GAS が開始メールを検知・登録したことを示します。監視開始や音声の到着を保証するものではありません。** アプリの監視中表示は、自分の開始IDに対応する `start-status.json` の状態が `monitoring` になったことを基準にします。

### アプリから渡すパラメータ

| パラメータ | 必須 | 内容 |
|---|---|---|
| `key` | 必須 | `KICK_SECRET` と一致する値 |
| `start_id` | 必須 | アプリの今回の開始操作を識別する UUID |
| `since` | 必須 | 開始操作の時刻。末尾が `Z` の ISO 8601 UTC |
| `speech_interval` | 任意 | `per_km` / `per_500m` / `interval:180` |

開始IDには `start_id` を使います。`sid` は GAS の予約名なので使いません。

### 検知後の発話間隔の同期

同じ開始IDで再度呼ばれた場合、GAS はメールを検索し直したり、セッションを再登録したりしません。`speech_interval` があれば、認証付きの `op=session-settings` で設定だけを更新します。セッションの受信日時も更新しません。

初回登録でも発話間隔を含めます。パラメータが省略または空なら送らず、サーバー側の設定を使います。値の許可リスト検証は Worker が行い、不正値は無視します。設定更新に失敗した場合は `ok:false` を返し、次のアプリからの呼び出しで再試行します。

## 診断と応答の読み方

`debugCheck` は、テスト用の新しい開始IDと現在時刻で検知処理を実行します。**実際にセッションを Worker へ登録し、メールを処理済みにすることがあるため、実走中には実行しないでください。** 最近のメールが見つからず `ok:true, found:false` になった場合、GAS の処理は成功していますが、Worker への書き込みは未確認です。

アプリからの呼び出しには、次のような JSON を返します。

| 結果 | 意味・対応 |
|---|---|
| `ok:true, found:true` | 新規登録成功。同じ開始IDの登録済み応答には `already:true` も付く |
| `ok:true, found:false` | 対象の未処理メールがない。処理済み候補があれば `already:true` が付く場合もある |
| `ok:false, error:"unauthorized"` | キーが未設定・不一致。`/exec` URL だけをブラウザで開いた場合にも返る |
| `WORKER_BASE is not set` | スクリプト プロパティの設定漏れ |
| `start_id must be a UUID` / `since must be ISO 8601 UTC` | 開始パラメータが欠落・不正。アプリの対応版と設定を確認 |
| `worker rejected: ...` | 初回登録を Worker が拒否。宛先とアップロードトークンを確認 |
| `ok:false, found:true` | 登録済み開始IDの発話間隔更新に失敗。次回呼び出しで再試行 |
| `detection failed; retry later` | その他の例外。Apps Script の実行記録と設定を確認 |

応答に LiveTrack のトークンは含めません。Apps Script の実行一覧が「完了」でも、応答の `ok` が成功とは限らないため、アプリの開始検知ログと合わせて確認してください。

## 自動管理する状態

次のプロパティは GAS が管理します。通常は手動で設定・削除しません。

| プロパティ | 用途 |
|---|---|
| `PROCESSED_MAIL_IDS` | 処理済みメールIDのJSON配列。直近20件を保持 |
| `LAST_MAIL_ID` / `LAST_SESSION_ID` | 最後に登録したメールとセッション。旧形式のメールIDも処理済み一覧へ取り込む |
| `LAST_START_ID` / `LAST_START_SESSION_ID` | 最後に登録したアプリ開始IDとセッションの対応。同じ開始操作での再登録を防ぐ |

処理済み一覧が不正なJSONや型なら処理はエラーになります。自動で消去して再登録することはありません。GAS 内の同時実行はスクリプトロックで直列化します。

## ローカルテスト

リポジトリのルートで実行します。

```bash
node gas/test_processed.cjs
```

メール選択、処理済み判定、開始時刻の条件、認証、発話間隔の転送などを模擬環境で確認します。実際の Google アカウントの権限、デプロイ設定、Worker への接続は別途確認が必要です。
