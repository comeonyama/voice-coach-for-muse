# UI/UX 仕様（現行）

2026-11-03 の再設計で確定した画面仕様です。それ以前のダークテーマ版の記録は、この文書では扱いません。

## デザインの基準

- **ライトテーマ**。参考は MyFitnessPal の画面の色とコンポーネント。
  - 背景: 薄い青から白へのグラデーション
  - カード: 白、角丸、柔らかい影
  - 文字: 黒基調、見出しは太字
  - アクション色: プライマリブルー（およそ #0066EE 系）
  - 緑は「受信中」「再生済み」などの状態アクセントに使う
- タブバーは作らない。単一画面（メイン）＋設定画面の構成。

## メイン画面（上下分割）

### 上部ゾーン

1. **ヘッダー**: 「Voice Coach for Muse」を1行で表示（Voice Coach を太字、for Muse を細字で区別）。右端に設定アイコン（歯車）。
2. **電源ボタン**: 画面中央の大きな円形ボタン。載せるのは電源シンボルの図形のみ。
   - 待機中: 白い円に薄グレーの電源アイコン
   - 受信中: プライマリブルーで塗った円に白の電源アイコン
   - 押下で受信の開始／停止をトグルする。
3. **状態テキスト**: ボタンの直下。
   - 待機中: 「受信停止中」（グレー）
   - 受信中: 「受信中」（緑。ドット併記可）
   - 開始検知の待機・監視中の表示は、配信基盤の開始状態（start-status）に基づいて切り替わる。当日のキュー名では判定しない。
4. 上部にはこれ以外の要素を置かない（「最終受信」などのラベル行、トグル類、テストボタンは設定画面側）。

### 下部ゾーン（コーチング履歴）

- 見出し「コーチング履歴」と「すべて見る」。
- 履歴は **1件のコーチングメッセージ = 1枚のカード**。カードには本文（半角数字）と時刻を載せる。
- 状態の区別:
  - **待機中（未再生）**: 青の枠線＋「待機中」バッジで目立たせる
  - **再生済み**: 控えめに。「再生済み」バッジ（緑チェック）で状態だけ示す
- 状態は再生管理（再生済み ID）と連動し、再生が終わったカードはその場で通常表示に切り替わる。
- メインには最新ランの直近3件。すべては「すべて見る」から開く。
- リセットは履歴画面側に置き、全ランが対象で音声が再び流れることを説明する確認ダイアログを出す。
- 画面の最下部に、アプリのバージョンを小さく表示する（例: 「バージョン 1.4.2 (13)」。値はビルド設定から動的に取得）。

## 開始時の案内ダイアログ

- 電源ボタンで受信を開始したときに表示する。
  - 文案: 「ウォッチでアクティビティを開始してください。／すでに開始済みの場合は、Muse に「アクティビティ監視を開始して」と依頼してください。」
- 「今後このダイアログは表示しない」オプション付き（UserDefaults に永続化）。設定画面の「開始時の案内を表示」トグルで再表示できる。

## 設定画面

- **接続先**: キュー URL は生のまま表示・編集できる。検知スクリプト URL と合言葉（KICK_SECRET）もここで設定する。変更は停止中のみ。
- **発話間隔**: セグメント選択で「1km / 500m / 3分」。初期値は3分、UserDefaultsに保存。受信・再生中も変更可能。約30秒ごとのキックで同期し、前回送信からの距離・時間で次回を判定する。受信確認間隔とは別。
- **音声テスト**: サウンドチェックとして配置。音楽再生中に押すと、ダッキング（音量低下と復帰）を確認できる。
- **開始中は自動ロックを防止**: トグル。
- **バックグラウンド受信**: 位置情報を使う理由と、記録・送信しないことの説明を表示する。「常に許可」への段階的な要求もここから。
- **詳細ログ**: イベントログの独立画面。診断情報（UTC 時刻・ID・内部 API の情報、再生監視の記録）はここにだけ残す。

## 再生まわりの仕様

- 再生は MP3（Muse TTS）が主経路。再生中は音楽をダッキングし、終了後に元の音量へ戻す。
- 音声のない（audio なし）メッセージは、監視側で MP3 配信に失敗したときのフォールバックとして、アプリ側の読み上げ（iOS TTS）で再生される。
- 再生に失敗したメッセージは履歴に記録され、詳細ログに診断情報が残る。

## 記事用スクリーンショットの撮影手順

実際に受信した内容を使い、画面を加工せず撮影できます。配信 URL やログが写る設定画面は記事用画像に含めないでください。

### メイン画面

1. アプリを起動し、受信を停止した状態で接続先などの設定を済ませる。
2. 「コーチング開始」で記事に掲載してよい本文を受信し、音声の終了を待つ。
3. 待機中カードと再生済みカードが見える位置で撮影する。受信中の状態を撮る場合は、電源ボタンが青く表示されている間に行う。
4. 実機はサイドボタン＋音量を上げるボタンを同時に短く押す。Simulator はメニューの File → Save Screen（⌘S）。

### 履歴画面

1. メインの「コーチング履歴」横にある「すべて見る」をタップ。
2. ラン見出しと2〜3件の本文が見える位置で撮影。ID や配信 URL は表示されない。
3. 撮影途中でアプリを終了しない（履歴はサーバー保存分と端末内表示の統合のため、状態が変わる場合がある）。
